# First project case study

Use this brief when the first real project is ready. This document is not published as website content. The project list stays empty until the owner provides and approves the details.

- **Project name and context:** personal project, professional work, or learning exercise.
- **Problem and audience:** who needs it and what problem it addresses.
- **Your contribution:** decisions and implementation you personally owned.
- **Status:** what is implemented, demonstrated, deployed, or still planned.
- **Architecture:** the actual request/data flow and major components; an accurate diagram is useful here.
- **Tradeoffs:** one or two decisions, alternatives considered, and why you chose them.
- **Evidence:** reproducible example, demo, or measured result with its conditions. Omit unsupported metrics.
- **Stack:** technologies actually used.
- **Links:** public repository, live demo, or documentation; omit unavailable links.
- **Next steps:** known limitations and the next improvement.

Once approved, add a reviewed entry to `apps/web/src/content/projects.ts` using its existing Project type. Case-study sections can cover Problem, My contribution, Architecture and tradeoffs, and Results. Keep employer work distinct from personal projects and include only public-safe details. Do not add placeholder entries to the published data.
